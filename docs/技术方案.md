# 茶屿 TEA ISLAND · 门店运营系统 技术方案

**版本** v0.1（MVP1 设计基线）
**范围** 单店（S1），预留多店与外卖渠道扩展
**市场** 马来西亚（DuitNow / SST 6% / PDPA）
**配套原型** `/milk-tea-ops`（可直接在浏览器打开）

---

## 0. 一页纸摘要

| 维度 | 决策 |
|---|---|
| 交易模型 | 先付款后制作（pay-first），`PAID` 是唯一「承认」事件 |
| 计价 | 标价含税，SST 6% 内扣；`base = round(total / 1.06)`，`tax = total - base` |
| 工单粒度 | 整单领取、整单完成；订单内**每杯一行**（杯贴、勾选、退单以杯为单位） |
| 库存 | 收款即扣（外卖改为接单即扣）；BOM 带杯型系数；损耗独立记账 |
| 会员 | 手机号归一化唯一；积分/储值走流水（ledger），不存裸余额 |
| 语言 | 中文默认 + 英文；界面切换，小票双语并排，杯贴中文优先 |
| 硬件 | 浏览器 PWA + 本地打印 agent（小票 ESC/POS，杯贴 TSPL 位图） |
| 金额 | 一律整数「分」（sen），禁止浮点 |
| 渠道 | `channel` + `payment_status` 从第一天独立，外卖只留接口不实现 |

## 1. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  客户端（浏览器 / 平板 PWA，可离线）                          │
│  收银 POS  │  制作看板 KDS  │  后台 Back Office  │  客显      │
└───────────────┬──────────────────────────────────────────────┘
                │ HTTPS / JSON（离线时写入 IndexedDB 队列）
┌───────────────▼──────────────────────────────────────────────┐
│  API 层（单体应用，模块化边界）                                │
│  ┌─────────┬─────────┬─────────┬─────────┬──────────────┐   │
│  │ 订单域  │ 支付域  │ 库存域  │ 会员域  │ 报表域        │   │
│  └─────────┴─────────┴─────────┴─────────┴──────────────┘   │
│  事件总线（同进程）：order.paid / item.ready / stock.low …    │
└───────┬──────────────────┬───────────────────┬──────────────┘
        │                  │                   │
   PostgreSQL         本地打印 agent      外部适配器
   （单库单事务）      （localhost:17800）  DuitNow PSP / 外卖平台
```

**为什么先不做微服务**：单店日均 200–500 单，QPS 峰值 < 20。一个单体 + 清晰模块边界足够支撑到 5–10 家店；过早拆分只会让「一笔交易跨四个服务」这种最需要强一致的地方变成分布式事务。

**必须从第一天做对的三件事**
1. 金额用整数分；
2. 所有状态变更写事件/流水（ledger），不覆盖历史；
3. 支付回调幂等 + 状态机单向流转。

## 2. 领域模型

### 2.1 实体关系

```
store 1─n order 1─n order_item 1─n order_item_modifier
  │        │            │
  │        └─n payment  └─n (BOM) ─→ ingredient
  │        └─n refund
  │        └─1 member ─n point_ledger
  │                  └─n wallet_ledger
  │                  └─n member_coupon
  └─n stock_movement (ref: order / waste / purchase / audit)
```

### 2.2 表结构（PostgreSQL）

> 金额字段统一 `*_sen INT`；时间统一 `TIMESTAMPTZ`；所有业务表带 `store_id`。

```sql

CREATE TABLE store (
  id            TEXT PRIMARY KEY,              -- 'S1'
  name_zh       TEXT NOT NULL,
  name_en       TEXT NOT NULL,
  addr          TEXT,
  phone         TEXT,
  sst_no        TEXT,                          -- 小票必须打印
  price_mode    TEXT NOT NULL DEFAULT 'inclusive',  -- inclusive | exclusive
  tax_rate      NUMERIC(5,4) NOT NULL DEFAULT 0.06,
  service_rate  NUMERIC(5,4) NOT NULL DEFAULT 0,
  default_lang  TEXT NOT NULL DEFAULT 'zh',
  business_day_cutoff TIME NOT NULL DEFAULT '04:00'  -- 营业日切分点
);

-- 商品
CREATE TABLE product (
  id            TEXT PRIMARY KEY,
  store_id      TEXT REFERENCES store(id),
  cat           TEXT NOT NULL,
  name_zh       TEXT NOT NULL,
  name_en       TEXT,
  price_sen     INT  NOT NULL,                 -- 含税标价
  price_delivery_sen INT,                      -- 外卖价（预留）
  emoji         TEXT,
  color         TEXT,
  tag           TEXT,
  active        BOOLEAN DEFAULT TRUE
);

-- 选项组 / 选项（modifier，不建组合 SKU）
CREATE TABLE option_group (
  id       TEXT PRIMARY KEY,                   -- size / sugar / ice / topping
  name_zh  TEXT, name_en TEXT,
  type     TEXT NOT NULL,                      -- single | multi
  max_pick INT DEFAULT 1,
  required BOOLEAN DEFAULT TRUE,
  sort     INT DEFAULT 0
);
CREATE TABLE option_item (
  id        TEXT PRIMARY KEY,
  group_id  TEXT REFERENCES option_group(id),

  price_sen INT DEFAULT 0,
  sort      INT DEFAULT 0
);

-- 配方（BOM）
CREATE TABLE recipe_item (
  product_id    TEXT REFERENCES product(id),
  ingredient_id TEXT REFERENCES ingredient(id),

);

-- 原料
CREATE TABLE ingredient (
  id        TEXT PRIMARY KEY,
  name_zh   TEXT, name_en TEXT,
  unit      TEXT NOT NULL,                     -- g / ml / 个 / 份 / 张

  min_stock NUMERIC(12,3) NOT NULL DEFAULT 0,

);

-- 订单
CREATE TABLE "order" (
  id             TEXT PRIMARY KEY,
  store_id       TEXT REFERENCES store(id),
  no             TEXT NOT NULL,                -- 'A012'（门店当日流水号）

  channel        TEXT NOT NULL DEFAULT 'walkin',   -- walkin|grab|foodpanda|self
  pickup_type    TEXT NOT NULL DEFAULT 'takeaway', -- takeaway|dinein
  member_id      TEXT REFERENCES member(id),
  status         TEXT NOT NULL,                -- 见状态机

  subtotal_sen   INT NOT NULL,                 -- 含税小计
  discount_sen   INT NOT NULL DEFAULT 0,
  coupon_sen     INT NOT NULL DEFAULT 0,
  points_sen     INT NOT NULL DEFAULT 0,
  total_sen      INT NOT NULL,                 -- 顾客实付（含税）
  base_sen       INT NOT NULL,                 -- 不含税收入
  tax_sen        INT NOT NULL,                 -- SST
  cogs_sen       INT NOT NULL,                 -- 理论成本
  points_earned  INT NOT NULL DEFAULT 0,
  points_used    INT NOT NULL DEFAULT 0,
  discount_meta  JSONB,                        -- {type,value,reason,source}
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  paid_at        TIMESTAMPTZ,
  claimed_at     TIMESTAMPTZ,
  ready_at       TIMESTAMPTZ,
  called_at      TIMESTAMPTZ,
  completed_at   TIMESTAMPTZ,

  void_reason    TEXT,
  seed           BOOLEAN DEFAULT FALSE

CREATE INDEX idx_order_store_paid ON "order"(store_id, paid_at DESC);
CREATE INDEX idx_order_status ON "order"(store_id, status) WHERE status IN ('paid','preparing','ready');

-- 订单行 = 一杯
CREATE TABLE order_item (
  id          BIGSERIAL PRIMARY KEY,
  order_id    TEXT REFERENCES "order"(id) ON DELETE CASCADE,
  seq         INT NOT NULL,                    -- 1/3, 2/3
  product_id  TEXT,
  name_zh     TEXT, name_en TEXT,
  size        TEXT, sugar TEXT, ice TEXT,
  note        TEXT,
  unit_price_sen INT NOT NULL,
  cogs_sen    INT NOT NULL,
  usage       JSONB NOT NULL,                  -- {ingredient_id: qty}
  status      TEXT NOT NULL DEFAULT 'queued',  -- queued|done|void
  label_printed_at TIMESTAMPTZ,
  done_at     TIMESTAMPTZ,
  UNIQUE (order_id, seq)
);

CREATE TABLE order_item_modifier (
  order_item_id BIGINT REFERENCES order_item(id) ON DELETE CASCADE,
  group_id  TEXT, option_id TEXT,
  name_zh   TEXT, name_en TEXT,
  price_sen INT DEFAULT 0
);

-- 支付流水（一单可多笔）
CREATE TABLE payment (
  id         BIGSERIAL PRIMARY KEY,
  order_id   TEXT REFERENCES "order"(id),
  method     TEXT NOT NULL,                    -- cash|duitnow|balance|card|comp
  amount_sen INT NOT NULL,
  tendered_sen INT, change_sen INT,
  ref        TEXT,                             -- PSP txn id / 钱包流水号
  status     TEXT NOT NULL DEFAULT 'success',  -- success|pending|failed|refunded
  at         TIMESTAMPTZ DEFAULT now()
);
CREATE UNIQUE INDEX uq_payment_ref ON payment(ref) WHERE ref IS NOT NULL;

CREATE TABLE refund (
  id         BIGSERIAL PRIMARY KEY,
  order_id   TEXT, payment_id BIGINT,
  amount_sen INT, reason TEXT,
  status     TEXT NOT NULL DEFAULT 'pending',  -- pending|processing|done|failed
  psp_ref    TEXT,
  created_at TIMESTAMPTZ DEFAULT now(),
  done_at    TIMESTAMPTZ
);

-- 库存流水（唯一的库存事实来源）
CREATE TABLE stock_movement (
  id        BIGSERIAL PRIMARY KEY,
  store_id  TEXT, ingredient_id TEXT,
  qty       NUMERIC(12,3) NOT NULL,            -- 负数为出库
  reason    TEXT NOT NULL,                     -- sale|void|waste|purchase|stocktake|adjust
  ref       TEXT,                              -- order_id / waste_id
  at        TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_move_ing ON stock_movement(ingredient_id, at DESC);

-- 会员
CREATE TABLE member (
  id            TEXT PRIMARY KEY,
  store_id      TEXT,
  phone         TEXT NOT NULL UNIQUE,          -- 归一化 +60XXXXXXXXX
  name          TEXT,                          -- 选填
  tier_id       TEXT NOT NULL DEFAULT 't0',
  points        INT NOT NULL DEFAULT 0,        -- 冗余快照，真相在 point_ledger
  balance_sen   INT NOT NULL DEFAULT 0,        -- 冗余快照，真相在 wallet_ledger
  total_spent_sen INT NOT NULL DEFAULT 0,
  joined_at     DATE NOT NULL DEFAULT CURRENT_DATE,
  pdpa_consent_at TIMESTAMPTZ,
  marketing_opt_in BOOLEAN DEFAULT FALSE
);

CREATE TABLE point_ledger (
  id BIGSERIAL PRIMARY KEY, member_id TEXT, order_id TEXT,
  delta INT NOT NULL,                          -- +发放 / -核销 / -过期
  reason TEXT,                                 -- earn|redeem|expire|adjust|void
  balance_after INT NOT NULL,
  at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE wallet_ledger (
  id BIGSERIAL PRIMARY KEY, member_id TEXT,
  delta_sen INT NOT NULL,                      -- 充值为正，消费为负
  kind TEXT NOT NULL,                          -- topup|bonus|spend|refund|adjust
  principal_sen INT DEFAULT 0,                 -- 本金部分（可退）
  bonus_sen INT DEFAULT 0,                     -- 赠送部分（不可退）
  balance_after_sen INT NOT NULL,
  at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE coupon (
  id TEXT PRIMARY KEY, code TEXT UNIQUE NOT NULL,
  name_zh TEXT, name_en TEXT,
  type TEXT NOT NULL,                          -- amount|percent
  value INT NOT NULL,
  max_discount_sen INT,
  min_spend_sen INT DEFAULT 0,
  member_id TEXT,                              -- NULL = 公开券
  expires_at DATE,
  used BOOLEAN DEFAULT FALSE,
  used_order_id TEXT
);

-- 打印任务
CREATE TABLE print_job (
  id BIGSERIAL PRIMARY KEY,
  order_id TEXT, type TEXT NOT NULL,           -- receipt|label
  payload JSONB NOT NULL,
  status TEXT NOT NULL DEFAULT 'queued',       -- queued|printing|done|failed
  retry INT DEFAULT 0,
  error TEXT,
  printer TEXT,
  created_at TIMESTAMPTZ DEFAULT now(),
  done_at TIMESTAMPTZ
);

-- 审计
CREATE TABLE audit_log (
  id BIGSERIAL PRIMARY KEY, store_id TEXT,
  actor TEXT,                                  -- staff_id
  type TEXT NOT NULL,                          -- discount|comp|void|exchange|waste|topup|price_change
  ref TEXT, amount_sen INT,
  detail JSONB,
  at TIMESTAMPTZ DEFAULT now()
);
```

### 2.3 关键约束

| 约束 | 原因 |
|---|---|
| `member.phone` UNIQUE | 防重复会员导致储值错乱 |
| `payment.ref` UNIQUE（部分索引） | 支付回调幂等的最后一道闸 |
| `order_item (order_id, seq)` UNIQUE | 杯序号是杯贴和勾选的锚点 |
| `stock_movement` 只增不改 | 盘点/对账/差异分析都靠它 |
| 所有表 `store_id` | 多店时只是加过滤条件，不是改表 |

## 3. 状态机

### 3.1 订单

```
                    ┌──────────────┐
                    │ PENDING_PAY  │  已下单未付款（不进 KDS、不扣料）
                    └──────┬───────┘
              ┌────────────┴────────────┐
        超时/取消                    支付成功
              │                         │
        ┌─────▼─────┐            ┌──────▼──────┐
        │ CANCELLED │            │    PAID     │  ← 扣料、出杯贴、发积分
        └───────────┘            └──────┬──────┘
                                        │ 员工领取
                                 ┌──────▼──────┐
                                 │  PREPARING  │  整单在制作
                                 └──────┬──────┘
                                        │ 全部杯 done
                                 ┌──────▼──────┐
                                 │    READY    │  ← 自动叫号
                                 └──────┬──────┘
                                        │ 已取餐
                                 ┌──────▼──────┐
                                 │  COMPLETED  │
                                 └─────────────┘
```

退款是旁支：`PAID|PREPARING|READY → VOID`（退单，回滚库存与积分）。
`COMPLETED` 不允许退单，只能走「售后单」另开一笔。

### 3.2 杯子

```
QUEUED ──(制作员勾选)──► DONE
   │
   └──(整单退单)──► VOID
```
只有两态。**没有 MAKING**——因为工单是整单领取的，杯子的中间态没有业务含义。

### 3.3 状态转换表

| 当前 | 事件 | 下一状态 | 副作用 | 失败处理 |
|---|---|---|---|---|
| PENDING_PAY | `payment.succeeded` | PAID | 扣料、写 payment、发积分、核券、生成杯贴任务 | 若已超时取消 → 自动退款 |
| PENDING_PAY | `timeout(15min)` | CANCELLED | 无 | 保留 15 分钟给晚到的回调 |
| PAID | `claim` | PREPARING | 记录 claimed_at、打杯贴 | 并发领取用乐观锁 |
| PREPARING | `finish` | READY | 校验所有杯 done，记录 ready_at，触发叫号 | 有未完成杯 → 拒绝 |
| READY | `pickup` | COMPLETED | 记录 completed_at | — |
| PAID/PREPARING/READY | `void` | VOID | 回滚料、冲销积分、退款 | 已 COMPLETED 拒绝 |

### 3.4 支付状态（与订单状态解耦）

`payment_status` 独立存在，是为外卖渠道准备的：

| 场景 | 值 |
|---|---|
| 堂食现金/DuitNow/储值已收 | `paid` |
| 外卖平台代收，待结算 | `platform_pending` |
| 平台已结算（对账完成） | `settled` |
| 已退款 | `refunded` |
| 免单 | `comp` |

> 报表口径：营收只统计 `payment_status IN ('paid','comp')`；`platform_pending` 单独进「应收账款」。

## 4. 计价与税务

### 4.1 计算顺序（含税标价）

```
行单价 = product.price_sen + Σ option.price_sen
小计   = Σ 行单价 × 数量
折扣   = percent ? round(小计 × v/100) : v_sen        （上限 = 小计）
券     = percent ? round(小计 × v/100) : v×100          （受 max_discount / min_spend 约束）
积分   = min(可用积分, floor((小计-折扣-券) × 0.5 / 5)) × 5
合计   = 小计 - 折扣 - 券 - 积分                        （≥ 0）
税前   = round(合计 / (1 + 0.06))
税额   = 合计 - 税前                                   ← 减法，不独立取整
```

**为什么税额要减法**：两边各自 `round` 会出现 `9.34 + 0.55 = 9.89 ≠ 9.90`，日结差一分钱且永远查不出是哪单。任何时候都必须满足 `base + tax === total`。

### 4.2 示例

| 项目 | 金额 |
|---|---|
| 招牌珍珠奶茶 大杯 + 珍珠 | RM 13.40 |
| 满杯百香果 ×2 | RM 21.80 |
| 小计 | RM 35.20 |
| 积分抵扣 100 分 | −RM 5.00 |
| 合计（含税） | RM 30.20 |
| 其中 SST 6% | RM 1.71 |
| 不含税收入 | RM 28.49 |

### 4.3 报表口径

| 指标 | 公式 |
|---|---|
| 营业额（GMV） | Σ `total_sen`（含税） |
| 不含税收入 | Σ `base_sen`（**毛利基数**） |
| 应缴 SST | Σ `tax_sen` |
| 毛利 | 不含税收入 − Σ `cogs_sen` |
| 毛利率 | 毛利 ÷ 不含税收入 |
| 客单价 | 营业额 ÷ 订单数 |
| 折扣率 | Σ折扣 ÷ 小计 |

> 常见错误：拿含税营业额算毛利，毛利率凭空高 6%，报税时才发现钱不够。

### 4.4 现金流与成本分离

- **储值充值**不是收入，是负债（`wallet_ledger`）；消费时才确认收入。
- **赠送金**与本金分开记，退款只退本金。
- **免单**金额为 0，但 `cogs_sen` 照记——免单成本必须进「损耗/招待」科目，否则毛利虚高。

## 6. 接口设计（REST / JSON）

统一返回：`{ ok, data, error:{code,message} }`；写接口必须带 `Idempotency-Key`。

### 6.1 主要端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/menu` | 菜单（含选项组、双语） |
| GET | `/api/v1/members/lookup?q=6789` | 手机号后四位检索 |
| POST | `/api/v1/members` | 注册（手机号 + 选填姓名） |
| POST | `/api/v1/orders` | 创建订单（PENDING_PAY） |
| POST | `/api/v1/orders/{id}/pay-cash` | 现金收款 |
| POST | `/api/v1/orders/{id}/pay-duitnow` | 创建 DuitNow 支付意图，返回二维码 |
| POST | `/api/v1/orders/{id}/pay-balance` | 储值支付 |

## 7. DuitNow 接入（马来西亚）

### 7.1 角色

商户**不直连 PayNet**，通过 PSP/收单机构（iPay88、Razer Merchant Services、Billplz、SenangPay、银行收单）拿 API。DuitNow QR 是 EMVCo 格式，PSP 负责把它渲染成二维码串。

### 7.2 只用动态二维码

| | 静态 QR | 动态 QR |
|---|---|---|
| 金额 | 顾客自己输入 | 商户下发，绑定订单 |
| 对账 | 只能靠金额+时间猜 | 每笔有唯一 ref |
| 篡改风险 | 高 | 无 |

**结论：一律用动态 QR**（amount + orderNo + 有效期）。

### 7.3 回调处理（四道闸）

```
1. 验签        HMAC / 公钥验签，失败直接 401，不落库
2. 幂等        INSERT INTO payment(ref) ... ON CONFLICT DO NOTHING
               影响行数 = 0 → 已处理过，直接返回 200
3. 校验金额    回调 amount 必须 === order.total_sen，不等则告警 + 人工介入
4. 校验状态    仅当 order.status = PENDING_PAY 才流转；否则记异常队列
```

### 7.4 回调丢失与对账

| 问题 | 对策 |
|---|---|
| 回调丢失 | 前端轮询 `/orders/{id}` 兜底 + 每 30s 主动查询 PSP 状态 |
| 回调晚到（订单已超时） | 订单保留 15 分钟；超窗到账 → 自动原路退款并告警 |
| 重复回调 | `payment.ref` 唯一索引 |
| 账实不符 | 每日拉取 PSP 结算文件，与 `payment` 表逐笔核对，差异进 `reconciliation_diff` |

**没有对账功能的收银系统，月底一定对不上账。** 这是必须做的，不是可选项。

### 7.5 退款是异步的

```
退款申请 → status='processing' → 等 PSP 回调 → status='done'
```
在 `processing` 期间：库存可回滚、积分可冲销，但**订单不能标记为已退款完成**，否则财务口径会错。

## 8. 库存与 BOM

### 8.1 扣减时机

| 方案 | 优点 | 缺点 |
|---|---|---|
| 下单预占 | 不会超卖 | 弃单多、要释放，复杂度高 |
| **收款即扣（采用）** | 简单、与收入对齐 | 退单要回滚 |
| 制作完成扣 | 最准 | 改单要回滚两次 |

外卖单例外：平台单在 `ACCEPTED` 时就扣（因为平台已承诺生产），不等结算。

### 8.2 杯型系数

`usage = recipe.qty × (size == L ? 1.3 : 1)`，但 `scale_with_size=false` 的条目（珍珠、布丁、柠檬）**不放大**——小料是固定份量。加料再单独叠加。

### 8.3 损耗与盘点差异

```
理论用量 = Σ(每杯 BOM 用量 × 销量)
实际用量 = 期初 + 采购 - 期末盘点
差异     = 实际 - 理论
差异率   = 差异 / 理论
```

| 差异率 | 判断 |
|---|---|
| < 2% | 正常（称量误差、蒸发） |
| 2–5% | 查配方是否漂移、员工是否多放 |
| > 5% | 重点查：内盗、试饮未记、报废未登 |

**损耗必须单独记 reason**（打翻/过期/试饮/员工餐），否则差异分析没有抓手。

### 8.4 补货点

`补货点 = 日均消耗 × 采购提前期 + 安全库存`，而不是「低于安全线才提醒」。系统应该给出「建议采购量」而不是一个红字。

## 9. 会员

### 9.1 手机号归一化

```
'012-345 6789'  →  去掉非数字 → '0123456789'
'60123456789'   →  去掉 60   → '123456789'
'+60123456789'  →               '123456789'
统一存 '+60' + 9 位，建唯一索引
```

不做归一化，三个月后会员库里会有同一人三个账号，储值余额对不上——这是最常见的运营事故。

### 9.2 积分

- 获取：`floor(实付RM × 1 × 等级倍率)`
- 消耗：100 分 = RM5，单笔最多抵 50%
- 过期：建议 12 个月滚动过期，过期前 30 天推送

必须写 `point_ledger`，`member.points` 只是冗余快照（每次事务内同步更新，定期用流水校准）。

### 9.3 储值

```
充值 100 → principal 10000sen, bonus 0
充值 100 送 10 → principal 10000sen, bonus 1000sen（两条 ledger）
消费 30 → 先扣 bonus 再扣 principal（或按比例，需在制度里写明）
退款 → 只退 principal
```

**储值是预收款 = 负债**，后台必须单独展示「储值负债总额」，不能算进营业额。

### 9.4 PDPA（个人数据保护法）

| 要求 | 实现 |
|---|---|
| 收集告知 | 注册时展示用途说明 |
| 数据最小化 | 只要手机号，姓名选填 |
| 展示脱敏 | 后台默认 `012-*** 6789`，看全号需权限 |
| 营销同意 | `marketing_opt_in` 独立开关，默认 false |
| 删除权 | 提供匿名化接口（保留订单金额，抹掉手机号/姓名） |

### 9.5 等级

按累计消费升级：0 / 500 / 1500 / 3000（RM）。
权益 = 折扣（0/2/5/8%）+ 积分倍率（1/1.2/1.5/2）。
**等级折扣不自动叠加**，由收银员显式点击「应用会员折扣」，避免与券叠加算错。

## 10. 打印子系统

### 10.1 为什么需要本地 agent

浏览器不能直接驱动热敏打印机。必须有一个本地服务（`localhost:17800`），接收 HTTP 请求，转成打印机指令走 USB/网口。

```
浏览器 ──HTTP POST /print──►  本地 agent  ──USB/网口──►  打印机
```

### 10.2 两套指令集

| 设备 | 指令集 | 用途 |
|---|---|---|
| 小票机（80mm） | ESC/POS | 客户小票 |
| 标签机（50×40mm） | **TSPL** | 杯贴 |

**不能混用**。杯贴的中文必须**渲染成 1-bit 位图**再用 `BITMAP` 指令发送——标签机内置中文字库要么没有、要么极丑。这样做的好处：版式改动只改渲染层，不动打印机协议。

### 10.3 杯贴版式（50×40mm ≈ 400×320 dots @203dpi）

```
┌──────────────────────────────────┐
│ A012                      1/3    │  单号 32pt / 杯序
│ 招牌珍珠奶茶                     │  18pt
│ Signature Pearl Milk Tea         │   9pt
│ ────────────────────────────     │
│ 大杯 · 半糖 · 少冰               │  16pt
│ +珍珠  +奶盖                     │  16pt
│ 备注 少放糖                      │  12pt
│ ▣▣▣▣▣        14:32              │  QR 20mm + 时间
└──────────────────────────────────┘
```

信息优先级：**单号 > 饮品名 > 糖冰 > 加料 > 备注**。
二维码内容 = `S1-20261105-A012-1`（订单号 + 杯序），扫一下能定位到具体哪杯。

### 10.4 打印时机

默认 **KDS 领取时打印**整单杯贴（避免标签在台面堆积、贴错杯）；可配置成「收款即打」（有些店习惯先贴杯排队）。

### 10.5 失败处理

`print_job` 表必须有 `status` 和 `retry`。**漏打一张杯贴 = 漏做一杯**，所以：

- 打印失败自动重试 3 次
- 超过 3 次在 KDS 上标红提示「重打」
- `label_printed_at` 落库，刷新页面不丢

## 13. 多店演进

现在只做四件事，成本近乎为零，事后补极痛：

1. 所有业务表带 `store_id`
2. 单号带店号：`S1-A012`
3. **营业日 ≠ 自然日**：按 `business_day_cutoff` 切分报表（夜班数据才对得上）
4. 配置（菜单/价格/税率/语言）走表，不硬编码

不做：门店调拨、总部下发、跨店会员。等第二家店开出来再设计，但上面四项让它们变成「加功能」而不是「重构」。

| # | 场景 | 系统行为 | 兜底 |
|---|---|---|---|
| 1 | 付款成功但订单已超时取消 | 自动原路退款 + 告警 | 人工核对回调队列 |

| 17 | 积分抵扣超额 | 上限 50%，自动收敛 | 后端 clamp |
| 18 | 跨零点打烊 | 按营业日归集 | `business_day_cutoff` |
